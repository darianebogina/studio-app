# Приложение для танцевальной студии

Мобильное веб-приложение (PWA) для одной танцевальной студии на одного преподавателя. Ученики регистрируются, покупают абонементы за наличные у преподавателя, записываются на занятия через календарь. Преподаватель ведёт учёт: оформляет покупки, создаёт и отменяет занятия, отмечает присутствие, что автоматически списывает занятия с абонемента ученика.

---

## Роли

**Ученик** — регистрируется сам, видит своё расписание, записывается на групповые занятия, видит остатки по абонементу и историю списаний.

**Преподаватель** — единственный, определяется по email в переменных окружения (`TEACHER_EMAIL`). Роль нельзя изменить через UI. Ведёт учёт абонементов, создаёт/отменяет занятия, отмечает присутствие.

---

## Функциональные требования

### Авторизация и регистрация

- Вход через **magic link на email** (Supabase Auth). Пароля нет.
- Регистрация собирает: email, имя, фамилия, телефон (телефон без верификации — просто контакт для преподавателя).
- Роль определяется автоматически: если email = `TEACHER_EMAIL` из env → teacher, иначе student.
- Восстановление доступа — по тому же magic link на email.

### Абонементы

Тарифы:

| Тариф | Цена | Что даёт |
|---|---|---|
| 4 занятия | 2600 ₽ | +4 групповых |
| 8 занятий | 3400 ₽ | +8 групповых |
| 4 + индив | 3400 ₽ | +4 групповых, +1 индив |
| 8 + индив | 4000 ₽ | +8 групповых, +1 индив |
| 16 занятий | 6000 ₽ | +16 групповых |
| Индив | 1800 ₽ | +1 индив |
| Разовое | 800 ₽ | +1 групповое |
| Разовое со съёмкой | 1200 ₽ | +1 групповое |

Правила:

- Абонементы **не сгорают автоматически**. Через 30 дней после покупки в карточке появляется плашка "Прошёл месяц с покупки".
- Преподаватель может **вручную аннулировать** абонемент (обнулить остатки).
- **Два раздельных счётчика:** `group_remaining` и `individual_remaining`. Списание строгое — с групповых списываются только групповые, с индивов только индивы.
- У ученика может быть несколько активных абонементов. При списании — FIFO: сначала расходуется тот, что куплен раньше.
- Преподаватель оформляет покупку сам (за наличные) и указывает дату — можно задним числом.
- Если у ученика 0 занятий на балансе и преподаватель отмечает присутствие — показывается предупреждение, при подтверждении баланс уходит в минус, разбирается вручную.
- **Ученик не может записаться**, если у него 0 занятий → сообщение "купите абонемент".

### Занятия и календарь

- Стандартное регулярное расписание захардкожено в seed-скрипте на год вперёд.
- Два типа занятий: **Vogue** (групповое, открытая запись) и **Индив** (закрытое, привязано к конкретному ученику).
- Преподаватель может **создавать новые занятия** — выбирает тип, дату, время.
- Для индива при создании — выбор ученика из базы или ручной ввод имени "внешнего" ученика (не зарегистрированного в приложении).
- **Отмена занятия преподавателем** — soft delete (`status: cancelled`). Занятие остаётся видимым, но записываться нельзя.
- **Лимита учеников на занятие нет.**
- **Ограничений по времени** записи/отмены нет — можно записаться и отменить за минуту до начала.

### Запись и присутствие

- Ученик записывается на групповые занятия через дровер по клику на карточку.
- Ученик может отменить свою запись (в дровере занятия или во вкладке "Мои записи").
- Преподаватель в карточке занятия видит список записавшихся и отмечает "был/не был".
- После отметки "был" — списывается 1 занятие соответствующего типа с активного абонемента.
- Преподаватель может **добавить ученика на занятие вручную** (кейс: ученик забыл записаться).
- Преподаватель может **списать 1 занятие** с абонемента без привязки к конкретному занятию (кнопка в карточке ученика).

### Видимость в календаре

- Ученик видит: все групповые занятия + свои индивы (чужие индивы не видит).
- Преподаватель видит: все занятия, включая все индивы и внешних учеников.

## Экраны

### Ученик (3 вкладки в таб-баре)

1. **Главная** — профиль (имя, телефон), карточка абонемента с двумя счётчиками, плашка "Прошёл месяц" после 30 дней.
2. **Календарь** — горизонтальный день-стрип + список занятий выбранного дня. Полоски по цветам: фиолетовая = Vogue, розовая = свой индив, серая = отменённое. Плашка "Вы записаны" на своих записях.
3. **Мои записи** — предстоящие (можно отменить) и прошедшие (с пометкой "посещено"/"пропущено").

Дополнительно:
- **Дровер занятия** — открывается по клику. Инфа + кнопка "Записаться"/"Отменить запись".
- **Дровер истории** — открывается по клику на карточку абонемента. Все покупки и списания с датами.
- **Экраны входа и регистрации.**

### Преподаватель (3 вкладки в таб-баре)

1. **Главная (Сегодня)** — метрики (сколько занятий, сколько записанных), список сегодняшних занятий, FAB "+" для быстрого создания.
2. **Календарь** — то же, что у ученика, но с количеством записавшихся вместо статуса записи.
3. **Ученики** — список с поиском по имени/телефону, справа бэйдж с остатком абонемента (красный при 0/0).

Дополнительно:
- **Дровер занятия (для препода)** — список записавшихся с чекбоксами "был/не был", остаток абонемента у каждого имени, кнопки "Добавить ученика", "Сохранить", "Отменить занятие".
- **Карточка ученика** — контакты, текущий абонемент, кнопки "Оформить", "Списать", "Аннулировать", история списаний.
- **Форма создания занятия** — тип (Vogue/Индив), дата, время, для индива — выбор ученика или ручной ввод.
- **Форма оформления покупки** — выбор тарифа, дата покупки (можно задним числом).

## Схема базы данных

Пять таблиц. Ledger (журнал операций) — источник правды для истории и балансов.

### users

Все пользователи в одной таблице.

| Поле | Тип | Комментарий |
|---|---|---|
| id | uuid PK | из Supabase Auth |
| email | string UK | для magic link |
| phone | string | без верификации |
| first_name | string | |
| last_name | string | |
| role | enum | `student` \| `teacher` |
| created_at | timestamp | |

### subscriptions

Один активный абонемент = одна запись. Может быть несколько параллельно (FIFO при списании).

| Поле | Тип | Комментарий |
|---|---|---|
| id | uuid PK | |
| user_id | uuid FK → users | |
| plan | enum | тип тарифа (для отчётности) |
| group_total | int | сколько групповых куплено |
| group_remaining | int | сколько групповых осталось |
| individual_total | int | сколько индивов куплено |
| individual_remaining | int | сколько индивов осталось |
| purchased_at | date | указывает преподаватель, можно задним числом |
| is_active | boolean | ставится false при аннулировании |
| created_at | timestamp | |

### lessons

Все занятия — и групповые, и индивы — в одной таблице.

| Поле | Тип | Комментарий |
|---|---|---|
| id | uuid PK | |
| type | enum | `vogue` \| `individual` |
| starts_at | timestamp | дата и время начала |
| duration_min | int | длительность в минутах |
| status | enum | `scheduled` \| `cancelled` |
| assigned_student_id | uuid FK → users | nullable, только для индивов |
| external_student_name | string | nullable, для индивов "не из студии" |
| created_at | timestamp | |

У индива заполнено `assigned_student_id` **или** `external_student_name`. У группового оба NULL.

### bookings

Запись ученика на конкретное занятие.

| Поле | Тип | Комментарий |
|---|---|---|
| id | uuid PK | |
| lesson_id | uuid FK → lessons | |
| user_id | uuid FK → users | |
| status | enum | `booked` \| `attended` \| `missed` \| `cancelled` |
| booked_at | timestamp | |
| attended_at | timestamp | nullable |

На индивы bookings могут создаваться автоматически при создании индива (для единообразия).

### ledger

Журнал всех операций. Показывается пользователю как история.

| Поле | Тип | Комментарий |
|---|---|---|
| id | uuid PK | |
| user_id | uuid FK → users | |
| event_type | enum | `purchase` \| `deduction` \| `reset` |
| lesson_kind | enum | `group` \| `individual` \| null |
| group_delta | int | +8 при покупке, -1 при списании и т.д. |
| individual_delta | int | |
| subscription_id | uuid FK → subscriptions | nullable |
| lesson_id | uuid FK → lessons | nullable |
| note | string | текст для UI: "Vogue · 19:00", "Покупка «8 + индив»", "Абонемент аннулирован" |
| created_at | timestamp | |

**Инвариант:** сумма всех дельт по user_id из ledger = текущим остаткам в subscriptions. Ledger — источник правды, `subscriptions.remaining` — денормализованный кэш для быстрого чтения. Обновляем атомарно (транзакция или Postgres function).

## Стек

- **Фронт:** Next.js (App Router, TypeScript) + SCSS-модули (`*.module.scss`) + Radix UI (headless-компоненты) + lucide-react + date-fns
- **Бэк + БД + Auth:** Supabase (Postgres + Row Level Security + magic link)
- **Хостинг:** Vercel (автодеплой при push в main)
- **PWA-обёртка:** манифест + service worker → ученики "устанавливают" сайт на домашний экран телефона
- **Опционально в будущем:** Capacitor для публикации в App Store и Google Play

**Про Radix UI:** библиотека headless-компонентов (дровер, модалка, дропдаун, тултип и т.д.) — даёт готовую логику и доступность (фокус-менеджмент, клавиатура, ARIA), а стили пишутся самостоятельно в SCSS-модулях. Ставится по одной зависимости на компонент, например `@radix-ui/react-dialog`.

## План работ

### Этап 0. Проектирование ✅

Требования, схема БД, wireframes всех экранов.

### Этап 1. Setup

- Node.js через Homebrew, Git, GitHub CLI
- `npx create-next-app@latest` с TypeScript, App Router, src/, ESLint, без Tailwind, без React Compiler
- Установка SCSS: `npm install sass`
- Установка `@supabase/supabase-js`, `@supabase/ssr`, `lucide-react`, `date-fns`
- Radix-компоненты ставятся по мере надобности: `@radix-ui/react-dialog` (для дровера и модалки), `@radix-ui/react-dropdown-menu`, `@radix-ui/react-toast` и т.д.
- Структура папок: `src/app/`, `src/components/`, `src/lib/`, `src/types/`
- Push в GitHub, деплой на Vercel

### Этап 2. Supabase и БД

- Создание проекта в Supabase
- SQL: создание 5 таблиц по схеме
- SQL: Row Level Security policies (ученик видит только свои данные, препод видит всё)
- Seed-скрипт: генерация групповых занятий на год вперёд по регулярному расписанию
- Настройка magic link auth и шаблона письма
- Ключи Supabase в `.env.local`

### Этап 3. Auth и структура

- Экраны входа и регистрации
- Middleware для защиты роутов
- Логика роли: сверка email с `TEACHER_EMAIL`

### Этап 4. Ученик — читающие экраны

- Главная (профиль + абонемент)
- Календарь (список занятий по дням)
- Дровер занятия
- История списаний

### Этап 5. Ученик — действия

- Запись на занятие
- Отмена своей записи
- Вкладка "Мои записи"

### Этап 6. Преподаватель

- Список учеников
- Карточка ученика
- Оформление покупки абонемента
- Ручное списание и аннулирование (через Postgres functions для атомарности)
- Дровер занятия с отметками присутствия
- Создание нового занятия
- Отмена занятия (soft delete)

### Этап 7. Полировка

- Empty states, loading states, error states
- Toast-уведомления после действий
- Подтверждающие модалки на деструктивные действия
- PWA-манифест, иконки, `apple-touch-icon` метатеги
- Инструкция для учеников "как установить на телефон"

### Этап 8. Реальное использование

- Тестирование на 1-2 реальных учениках
- Сбор багов, правки
- Раздача всей студии

## Design system

- **Тёмная тема** (почти чёрный фон, белый текст)
- **Акцент:** зелёный `#00E676` (активная вкладка таб-бара, primary-кнопки)
- **Карточки занятий:** тёмно-серый фон, скруглённые углы, вертикальная цветная полоска слева = тип занятия
    - Vogue — фиолетовый (`#7F77DD`)
    - Индив — розовый (`#ED93B1`)
    - Отменённое — серый, весь блок приглушён
- **Плашки-теги:** "вы записаны" зелёная, "индив" розовая, "отменено" красным текстом
- **Дроверы** (bottom sheets) для дополнительной информации, форм, отметок присутствия
- **Таб-бар** снизу: 3 иконки + активная вкладка в pill-форме с подписью
